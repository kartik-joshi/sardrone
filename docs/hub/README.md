# sardrone-sim: simulated drone frames of people, with exact boxes

34,981 frames from 75 simulated search-and-rescue drone flights, with a box
around every visible person, exact by construction. Made for studying how
well person detectors trained in simulation work on real drone photos.

From [sardrone](https://github.com/kartik-joshi/sardrone), where a detector
fine-tuned on these frames alone scored 0.95 mAP@0.5 on simulated test
worlds and 0.01 on real drone photos (SARD). See the repository for the
full experiments.

## Load it

```python
import fiftyone.utils.huggingface as fouh

dataset = fouh.load_from_hub("{repo_id}")
```

## What is in it

| Split | Frames | Flights |
| --- | --- | --- |
| train | 24,667 | 54 |
| val | 2,861 | 6 (not in train) |
| test | 7,453 | 15, in worlds not used for train or val |

- 50,185 person boxes; 10,204 frames have no person in view (useful as
  negatives). 473 frames carry the tag `duplicate` (near-duplicates found
  with CLIP embeddings).
- No flight appears in more than one split. Frames from one flight are
  near-copies of each other, so splitting by frame would leak.
- Images: 1280 x 960 JPEG, from a downward-pitched camera on a PX4 x500
  drone in Gazebo Harmonic, flying a lawnmower search pattern.

## What a label means

`ground_truth` holds `person` boxes from the simulator's bounding-box
sensor, rendered from the same view at the same instant as the image. A
box covers only the **visible** pixels of a person: someone fully hidden
under a tree has no box, and a partly hidden person gets a box around the
visible part. Boxes are exact for what they define, not hand-drawn.

## Fields

| Field | Meaning |
| --- | --- |
| `ground_truth` | person boxes (visible pixels only) |
| `split` | train / val / test |
| `episode_id`, `world`, `world_id`, `seed` | which flight and which generated world |
| `world` | meadow, park or forest_edge |
| `altitude_m` | flight altitude: 15, 25 or 40 m |
| `time_of_day` | noon, golden_hour or dusk (sun direction and light) |
| `time_s`, `mission_state` | time into the flight, and what the drone was doing |
| `height_m` | drone height above ground at the frame |
| `num_people`, `expected_by_geometry` | person boxes in the frame, and people the camera geometry says are in view (hidden people make the first smaller) |
| `occlusion` | the world's tree-cover setting: `none` or `partial` |
| `clip_embedding` | CLIP ViT-B/32 image embedding (512 values) |

## Known limits

- Narrow content: three person meshes (standing, sitting, lying), two tree
  models, flat textured ground, no vehicles, no weather (fog is not
  rendered in this Gazebo setup).
- These frames are trivially distinguishable from real drone photos: a
  linear classifier on CLIP embeddings separates them from SARD 100 % of
  the time. Training on them alone does not transfer to real photos; mixing
  in a few hundred real images recovers most of the real-photo score.
